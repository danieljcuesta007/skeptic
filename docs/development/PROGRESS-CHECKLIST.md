# Manual milestone checkpoint workflow

After authorized development work, before stopping:

- [ ] Collect completed changes and distinguish prototypes from released features.
- [ ] Record checks actually run, counts/results and failures; no invented success.
- [ ] Record source repository, branch, full HEAD, staged/unstaged/untracked state.
- [ ] Record known limits, blocked reviews and next authorized action.
- [ ] Within explicit edit scope, update the existing canonical project STATUS.md.
- [ ] Update its linked development dashboard when component status changes.
- [ ] Preserve its existing Handoff; create/replace a handoff only for unfinished
      transfer work, and preserve durable outcomes before clearing one.
- [ ] Recheck freshness immediately before editing; coordinate concurrent ownership.
- [ ] Verify unrelated dirty work, brain HEAD/index and instructions are unchanged.
- [ ] Finish with DONE / VERIFIED / NOT VERIFIED / FILES / NEXT / SESSION.

The private project STATUS/dashboard remain canonical for personal project progress.
This checklist is a reusable source-development process, not a competing memory store.
If writes are unauthorized/unsafe, provide a chat checkpoint and disclose non-persistence.
Never silently change global preferences or automatically stage/commit/push the brain.
No hooks, watchers, launchd jobs or automatic synchronization are installed.
Approval references are provenance; they are not future commit/push/deploy permission.
